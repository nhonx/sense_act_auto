# Sense/Act Browser Automation System

A two-component browser automation architecture separating **DOM state sensing** (Component ABC) from **physical OS input actuation** (Component XYZ).

## System Architecture

```
 +------------------------+                  +-------------------------+
 | Component ABC (Sensor) |                  | Component XYZ (Actuation)|
 |  Chrome Extension V3   |                  |  Python OS Input Server |
 +-----------+------------+                  +------------+------------+
             |                                            |
      (WebSocket:8000)                             (HTTP POST:8001)
             |                                            |
             +------------------+  +----------------------+
                                |  |
                        +-------v--v--------+
                        |   Orchestrator    |
                        |   (Agent Glue)    |
                        +-------------------+
```

---

## 1. Component ABC — Chrome Extension (Sensor)

Located in `./component_abc`:
- **Strictly Read-Only:** No DOM `.click()`, `.focus()`, `dispatchEvent()`, or `chrome.debugger` API usage.
- **Element Indexing:** Scans visible interactive elements (`button`, `a`, `input`, `textarea`, `[role=button]`, `[contenteditable]`, etc.) with unique stable IDs (`el_001`, `el_002`) and viewport-relative `getBoundingClientRect()`.
- **Content Extraction:** Cleans DOM main regions into structured plain text.
- **Mutation Monitoring:** Observes DOM changes via `MutationObserver` and notifies Orchestrator.
- **Transport:** Connects via WebSocket to `ws://localhost:8000`.

### Installation:
1. Open Chrome and navigate to `chrome://extensions/`.
2. Enable **Developer mode** (top right toggle).
3. Click **Load unpacked** and select the `./component_abc` directory.

---

## 2. Component XYZ — OS-Level Input Controller (Actuator)

Located in `./component_xyz`:
- **Genuine OS Input:** Executes real hardware mouse and keyboard events using native OS APIs (via PyAutoGUI/PyObjC/uinput).
- **Human-like Bezier Curves:** Non-linear cursor motion with randomized control points, micro-jitter, and overshoot/correction behavior.
- **Realistic Typing:** Variable inter-keystroke intervals with optional typo simulation.
- **Inertial Scrolling:** Smooth wheel events with deceleration.
- **REST API:** Exposes endpoints on `http://localhost:8001` (`/move`, `/click`, `/type`, `/scroll`, `/wait`).

### Quick Start Setup with Miniconda

#### Step 1: Create & Activate Conda Environment
```bash
# Option A: Using environment.yml (Recommended)
conda env create -f environment.yml
conda activate sense_act

# Option B: Manual Conda environment creation
conda create -n sense_act python=3.10 -y
conda activate sense_act
pip install -r requirements.txt
```

#### Step 2: Run Component XYZ Actuator Service
```bash
python component_xyz/actuator.py
```

---


## 3. Orchestrator (Agent Glue)

Located in `./orchestrator`:
- Manages WebSocket bridge (`ws://localhost:8000`) for Component ABC.
- Translates DOM viewport coordinates into absolute OS screen coordinates (`viewport_to_screen`).
- Enforces hard rate limits (max actions per hour, cooldown periods).
- Coordinates AI decision loops safely.

### Execution:
```bash
python orchestrator/orchestrator.py
```

The project includes test scripts in `./tests/` to verify Component XYZ and Orchestrator standalone and together:

Tests direct OS-level shortcut keys, text typing, file saving, and closing apps:
```bash

python component_xyz/actuator.py

python tests/test_actuator_standalone.py
```

### Test Suite 2: Interactive HTML Test Page (`./tests/test_page.html`)
Open `./tests/test_page.html` in Chrome:
- **Mouse Trajectory Canvas:** Plots live Bezier mouse movements in real-time.
- **Event Trust Logger:** Displays logged click and key events, confirming `event.isTrusted === true` for genuine OS input.
